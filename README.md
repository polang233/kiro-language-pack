# Kiro Language Pack

Community language packs for the [Kiro IDE](https://kiro.dev/) user interface.

**English** · [简体中文](README.zh-CN.md)

Kiro ships English only and exposes no way to switch the display language of its own
panels. This repository builds installable language packs that translate the Kiro
interface, plus - optionally - the whole editor workbench, so a single extension gives you
a fully localized IDE.

Everything is generated from a build pipeline. Contributors maintain translation files and
a terminology glossary; the pipeline handles manifest generation, key filtering, coverage
measurement and packaging.

## Supported languages

| Locale | Language | Kiro UI | Workbench | Status |
| --- | --- | --- | --- | --- |
| `zh-cn` | 中文（简体）Simplified Chinese | 72 / 72 (100%) | 14184 / 15630 (90.7%) | Ready |

Measured against Kiro 1.0.228 (Code OSS 1.107.1). More languages are welcome - adding one
requires no code changes, see [Adding a language](#adding-a-language).

## Two editions per language

Each locale is published twice, because most people already run the official VS Code
language pack.

| Edition | Extension name | Contents | Size |
| --- | --- | --- | --- |
| **Full** (recommended) | `kiro-language-pack-<locale>` | Workbench baseline + Kiro strings. Self-contained, replaces the official VS Code language pack. | ~430 KB |
| **Add-on** | `kiro-language-pack-<locale>-addon` | Kiro strings only. For people who keep their existing VS Code language pack. | ~10 KB |

Both editions declare the same `languageId`, so **install exactly one of them**. Installing
the full edition next to the official VS Code pack means two extensions claim the same
locale, and which one wins is up to the host - don't do it.

## Install

From the extension view in Kiro (`Ctrl+Shift+X` / `Cmd+Shift+X`), search for the pack and
install it. Kiro uses the [Open VSX](https://open-vsx.org/) registry by default.

Or install a `.vsix` from [Releases](../../releases):

```
Command Palette -> Extensions: Install from VSIX...
```

## Switching the display language

A language pack contributes no settings of its own. The display language belongs to the
editor, and Kiro inherits the Code OSS mechanism unchanged:

1. Open the Command Palette (`Ctrl+Shift+P` / `Cmd+Shift+P`)
2. Run **Configure Display Language**
3. Pick the language, then restart Kiro

If that command is unavailable, edit `argv.json` directly:

```json
{
  "locale": "zh-cn"
}
```

| Platform | Path |
| --- | --- |
| Windows | `%USERPROFILE%\.kiro\argv.json` |
| macOS | `~/.kiro/argv.json` |
| Linux | `~/.kiro/argv.json` |

Restart Kiro afterwards. Set the value to `"en"` or delete the field to go back to English.

## What can and cannot be translated

This is the honest scope, measured rather than assumed. Run `npm run audit` to reproduce
the numbers on your own install.

| Surface | Reachable | Notes |
| --- | --- | --- |
| Editor workbench: menus, Command Palette, settings, SCM, terminal, notifications | Yes | Full edition only. Baseline from `microsoft/vscode-loc`. |
| Built-in extensions: Git, Markdown, npm, language support, themes | Yes | Full edition only. 92 bundles. |
| Kiro command titles, view names, spec editor toolbar, tree view welcome text | Yes | 107 of 183 localizable manifest strings are externalized as `%key%`, backed by 72 keys in `package.nls.json`. |
| Kiro settings descriptions, some command titles, some view names | **No** | 76 manifest strings are inline English literals with no `%key%` indirection. Nothing a language pack can do. |
| Kiro chat panel, spec panel, hook editor, powers panel | **No** | 346 webview bundles, ~12.9 MiB, compiled without an i18n layer. |
| Kiro runtime messages via `vscode.l10n.t()` | Prepared | Kiro declares `"l10n"` in its manifest but does not call the API yet. The build already emits a `contents.bundle` section, so these become translatable the day Kiro adopts it. |

The last two rows are upstream limitations, not missing work here. Reports generated by
`npm run audit` list every unreachable string and are meant to be attached to upstream
requests for wider i18n coverage.

To make the AI answer in your language, that is unrelated to the UI - add a steering
document, e.g. `.kiro/steering/language.md`.

## How it works

VS Code, and therefore Kiro, resolves UI strings through the language pack contribution
point. A pack is a code-free extension that declares:

```json
{
  "contributes": {
    "localizations": [{
      "languageId": "zh-cn",
      "languageName": "Chinese Simplified",
      "localizedLanguageName": "中文（简体）",
      "translations": [
        { "id": "vscode", "path": "./translations/main.i18n.json" },
        { "id": "kiro.kiroAgent", "path": "./translations/extensions/kiro.kiroAgent.i18n.json" }
      ]
    }]
  }
}
```

Each translation file maps module paths and keys to translated text. Keys that are absent
fall back to English silently, so a partial translation degrades gracefully instead of
breaking the UI. For built-in extensions the host loads both the manifest strings
(`contents.package`) and the runtime bundle (`contents.bundle`) from the language pack,
which is why `kiro.kiroAgent` can be targeted at all.

The pipeline:

```
Kiro installation ──(extract)──> metadata/kiro.json ─────┐
                                                         │
microsoft/vscode-loc ──(sync)──> upstream/<locale>/ ──────┼──(build)──> dist/<pack>/ ──(package)──> .vsix
                                                         │
src/i18n/<locale>/{overrides,kiro} ──────────────────────┘
                                                         └──(coverage)──> reports/
```

`metadata/kiro.json` is a snapshot of every localizable key in the installed build,
including the English source text. It serves three purposes:

- **Filtering.** Keys that do not exist in Kiro are dropped - 8108 of them for the Chinese
  pack, which is what keeps the artifact small.
- **Repair.** Because `vscode-loc` tracks the current VS Code release while Kiro lags
  behind, some inherited translations no longer match their source: a stale `{2}` renders as
  the literal text `{2}`, and a translated `command:` target turns a link into dead text.
  The build drops those, 21 of them for Chinese, so the string falls back to English instead
  of rendering wrong. Mismatches in files this repository maintains are reported instead,
  since those are our bugs.
- **Coverage.** It gives `coverage` a real denominator instead of a guess.

The snapshot is optional, so CI can build without Kiro installed - filtering and repair are
skipped in that case.

## Build from source

Requires Node.js 18.17 or newer.

```bash
npm install

npm run detect     # inspect the local Kiro install: version, NLS layout, extension ids
npm run extract    # snapshot the localizable surface into metadata/kiro.json
npm run audit      # measure how much of the Kiro UI a language pack can reach
npm run sync       # download the workbench baseline from microsoft/vscode-loc
npm run build      # assemble dist/<pack>/ for every locale and edition
npm run validate   # structural checks plus placeholder/icon/command-link integrity
npm run coverage   # translation coverage plus a list of untranslated keys
npm run package    # produce the .vsix files
```

Useful flags, passed after `--`:

```bash
npm run build -- --locale=zh-cn --mode=full
npm run build -- --no-filter          # keep keys absent from the local Kiro build
npm run sync -- --force               # re-download instead of using the cache
npm run sync -- --strategy=api        # list files via the GitHub API (needs GITHUB_TOKEN)
npm run package -- --skip-build
```

`npm run detect` cannot always guess where Kiro lives. Point it at the install root, the
directory containing `resources/app/package.json`:

```powershell
$env:KIRO_INSTALL_DIR = "C:\Users\<you>\AppData\Local\Programs\Kiro"
```

### Installing what you just built

Artifacts land in `dist/`, one `.vsix` per edition:

```
dist/kiro-language-pack-<locale>-0.1.0.vsix          full
dist/kiro-language-pack-<locale>-addon-0.1.0.vsix    add-on
```

Install exactly one of them, and uninstall the official VS Code language pack first if you
are installing the full edition:

1. Command Palette -> `Extensions: Install from VSIX...` -> pick the file
2. Command Palette -> `Configure Display Language` -> pick the language
3. Restart Kiro

Or from a shell, if `kiro` is on your PATH:

```powershell
kiro --install-extension dist\kiro-language-pack-zh-cn-0.1.0.vsix
```

To verify, check that the Kiro sidebar view titles are translated and that the spec editor
toolbar shows translated buttons when a file under `.kiro/specs/` is open.

To revert, uninstall the extension and set `locale` back to `"en"` in `argv.json`, or delete
the field, then restart.

## Repository layout

```
config.json                       single source of truth: publisher, version, locales, modes
src/
  manifest.template.json          extension manifest skeleton
  marketplace/README.<locale>.md  the page shown on the extension marketplace
  i18n/<locale>/
    glossary.json                 terminology contract for the locale
    kiro/<extId>.i18n.json        Kiro translations - the core asset of this project
    overrides/main.i18n.json      corrections to the upstream workbench baseline
scripts/                          the build pipeline
metadata/                         generated, gitignored
upstream/                         translation cache, gitignored
dist/                             build output, gitignored
reports/                          coverage and audit reports, gitignored
```

## Adding a language

No code changes required.

1. Append an entry to `locales` in `config.json`. Set `upstreamPackDir` to the matching
   directory in [vscode-loc](https://github.com/microsoft/vscode-loc/tree/main/i18n), or
   `null` if there is none - the full edition is then skipped for that locale.
2. Create `src/i18n/<locale>/glossary.json` and agree on the terminology first.
3. Create `src/i18n/<locale>/kiro/kiro.kiroAgent.i18n.json`. Copy the Chinese file and
   replace the values; the inline comments carry the English source.
4. Add `src/marketplace/README.<locale>.md`.
5. Run `npm run build && npm run coverage`.
